# 向上回报 / Report Back

（占位卷——魂已就位，待第一个真实回报样例出现时填实。）

## 这个读者

对面是**上下文很宽、但注意力很省**的编排者。它不缺背景，缺的是"我现在该据此做什么决定"。

## 主要漂移

回报最容易翻的车，和派发相反：不是话太少，是**把你干过的所有事都倒出来**。worker 倾向于证明自己干了活，于是流水账式地汇报过程，而编排者只需要那几条**会改变它下一步决策**的。

## 魂怎么应用

- **目标变成**：让上游用最少的注意力，做对下一步决策。
- **承重判断变成**：你这趟的结论是什么、它改变了什么、有没有需要上游拍板的分叉。
- 朝"决策相关性"压缩——过程细节给指针（"详见 X"），不倒进回报里。
- 同样照漂移地图查自己：是不是因为求稳，把一个本可自己定的分叉，包装成"请上游决定"推了上去？

## 真样例 · 本轮给 owner 的汇报（2026-06-30）

"改前"现成——本轮我好几次的汇报就踩了这个漂移：把干过的全倒出来，让 owner 自己从流水账里捞决策点。

**✗ 改前**（倾向证明"我干了活"）：
> 重写了 fix / execution / planning / consensus / review×3……字数 460 / 1733 / 1385……；582 个 l2 测试全过；ruff + mypy 干净；更新了 12 个测试；部署三面一致；test_run075 是预存的……〔再两屏细节〕

**✓ 改后**（压到"上游要据此做什么决定"）：
> 全部派发信已迁到 handoff 标准、测试全绿、已提交。**只一件要你拍板**：handoff 注册成永久概念 `handoff-authoring-standard@v1`，名字/定义你认不认？其余（字数 / 测试 / 部署细节）要看我给指针。

变化：上游一眼看到"要做什么决定"，过程细节降成按需取的指针。

**代理尺**：把回报丢给一个只想推进的编排者，问"读完，你下一步要做的决定是什么？"——一句话答得出 = 压对了；要从段落里捞 = 还在倒流水账。

**也照漂移地图查自己**：我是不是把本可自决的（commit 边界、测试归位）也包装成"请你定"推了上去？（本轮 owner 多次提醒"别什么都问"——正是这条漂移在我身上。）
