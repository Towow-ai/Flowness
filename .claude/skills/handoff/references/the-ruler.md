# 怎么验证 / The Ruler

这一卷回答：一封交接信（以及生成它的这套思维）好不好，怎么知道；改完是真变好、还是自我感觉良好。

## 为什么不能用"断言通过率 benchmark"

skill-creator 那套"列一堆断言、数通过率"，适合产物能一眼判真假的场景（CSV 有没有那一列）。我们的产物是**判断的质量**——"这封信有没有尊重读者的智能"——你没法用断言断出来。所以验证换一套；而且这套尺子的刻度，正好就是这个 skill 教的那些原则。

## 第一层 · 便宜的代理尺（免费，改一版测一版）

把信交给一个**全新的聪明 AI**，让它**先别干活**，只回答四个问题。这四问不是随便挑的——每一问都对着一种具体的翻车，问的方式正好能让那种翻车现形：

- **"用一句话说出这次要干成什么。"** 说不出，目标就是没在场、或被埋了——一个冷读者能不能一句话复述目标，直接暴露目标在不在对的海拔上。
- **"你必须先问、否则没法开工的问题有哪些？"** 它列出来的每一条，都是信里本该交够、却没交够的承重信息；它问得越多，信漏得越多。
- **"挑出你解不了的词、和跟干活无关的句子。"** 它解不了的，就是那些没落地的暗号（留着它只会脑补）；它觉得无关的，往往就是漏进来的内部账。这一问把两种噪音同时逼出来。
- **"你必须完成的打卡点是哪几个，拎得清吗？"** 拎不清，说明打卡点要么不够短、要么混在别的话里没冒出来。

再加一问最狠的，直接测那个核心张力：

> **这封信是把你当工具指挥，还是把问题和判断交给你？**

一封好信：目标一句话拎得出、几乎没有真问题、几乎挑不出噪音、打卡点清清楚楚、且明显是在"交判断"而不是"发命令"。

这把尺子免费，任何一版信、任何一类派发都能先跑。但它是**代理**，不是真相。

## 第二层 · 昂贵的真尺（地面真相）

真开一个接收会话，让它把活干完，看：**回头问了几次**（尤其问的是它本可以自己查/自己定的东西）、**瞎转的程度**、**质检一次过还是返工**、**有没有改了不该改的（越界）**。

总指标是一条：**返工次数**——在结果正确且没越界的前提下，这个明确的需求，它用了几趟做掉。

这就像评探索算法：destination 不能用来评（它本就探未知），只能评 path——给定固定的需求和固定的结果，它是不是走了最短的那条。

两条护栏，免得这把尺子被玩坏：
1. **返工次数必须挂在"结果正确且不越界"上。** 否则会奖励"又快又错"——三步交一个跑偏的答案，不该比五步交对的分高。
2. **测试任务必须是真·明确的**（fix 正好是）。任务本身含混时，合理的来回是真探索、不是返工，这把尺子会冤枉它。所以它只在明确任务族上用——而那正是我们要的靶场。

## 第三层 · 校准纪律（把稀缺的真验证花在刀刃上）

别凭"我读着觉得顺"改信——那是最不可信的（尤其写信的是 AI，天生偏爱"读着像模型平均输出"的东西）。

把昂贵的真跑，花在**校准便宜尺**上：代理尺说"这版没问题、噪音清零"，真会话是不是也确实更少返工、更少回头问。一旦代理尺被真会话证明预测得准，以后所有版本就都在本地用代理尺免费迭代，不用每改一句都烧一轮真会话。

## 闭环：路径越走越短

1. 丢给它一个明确任务，**看 trace**（不只看产物）——它怎么走的。
2. 找出哪一步的路比必要的长：回头问了本可自查的东西？因为某个暗号脑补跑偏了？因为信里没交某条承重判断而空转了？
3. 改 skill / 加 reference，把那条缺口补上。
4. 拿一个**同类**的新任务再跑，路径应当变短。

北极星不是某一次的分，是**同一任务族上，"到 done"的路径随迭代越来越短**。这就是"让自己多余"被量化成了一条下降曲线——一封完美的信，接收方永远不必回头问、不必找作者。
