# Support

Flowness is an Open Alpha research-and-engineering project. Community support should remain public whenever possible so answers become reusable.

## Use GitHub Issues for

- reproducible bugs;
- broken documentation or quickstart;
- release artifact / hash mismatch;
- security-safe conformance failures;
- public fixture defects.

## Use GitHub Discussions for

- Flow Engineering questions;
- architecture and RFC proposals;
- Failure Atlas cases;
- benchmark design;
- integration ideas;
- community Flow Clinics;
- “is this a Flow failure?” diagnosis.

## Do not use public Issues for

- security vulnerabilities;
- credentials, private repositories, or proprietary event logs;
- personal data;
- evaluator-private benchmark materials.

Use the private security reporting process in `SECURITY.md`.

## What to include in a support request

- Flowness release and source commit;
- installation environment;
- exact command;
- sanitized output;
- Work / Execution IDs where applicable;
- expected and observed state;
- artifact manifest hash;
- whether the issue is reproducible from a clean clone;
- relevant status label.

Support is best-effort. Open Alpha interfaces may change with release notes and migration guidance.
