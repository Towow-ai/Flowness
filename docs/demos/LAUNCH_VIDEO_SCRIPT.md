# 90-Second Launch Video Script

Two versions are provided. Use **Version A** before the Work Outlives Agents demo is runnable. Use **Version B** only after its release gate passes.

---

## Version A — current-safe launch

### 0–08s — The problem

Visual: multiple agent sessions finish; green checkmarks accumulate; one target system remains unchanged.

Voiceover:

> Your agent says it is done. The code may even pass. But did the work actually reach the system that needed it?

On-screen:

```text
Built ≠ Integrated ≠ Activated ≠ Accepted
```

### 08–22s — The abstraction shift

Visual: Prompt → Context → Harness → Loop → Graph → Flow.

Voiceover:

> We learned to engineer prompts, context, harnesses, loops, and graphs. The next object is the work itself—how it keeps moving through all of them.

On-screen:

> Flow Engineering: the engineering of work in motion.

### 22–42s — Flowness

Visual: stable Work core; context, graph, validators, and temporary agents form around it.

Voiceover:

> Flowness is a work-centered runtime for agentic software engineering. Humans define the goals, judgments, obligations, and irreversible boundaries. Execution is organized inside that field.

On-screen:

> Work persists. Agents assemble.

### 42–60s — What exists now

Visual: actual Assurance Kernel terminal output and trace.

Voiceover:

> The current Open Alpha includes a deterministic assurance kernel: isolated producers, independent review, a Finding that survives rework, and a fresh verdict over the successor result.

On-screen status:

```text
[RUNNABLE] Assurance Kernel
[INSPECTABLE] broader mechanism set
[DESIGNED] Work Outlives Agents demo
```

### 60–77s — Why open source

Visual: Failure Atlas cases, mechanism cards, architecture docs.

Voiceover:

> We are not publishing a perfect autonomous factory. We are publishing the mechanisms, failures, and research questions we accumulated while running agents over months—so others can learn, borrow, challenge, and build their own cognitive exoskeleton.

### 77–90s — Close

Visual: repo hero, three entry paths.

Voiceover:

> Learn from the Failure Atlas. Borrow one mechanism. Or build your own work-centered Harness.

On-screen:

> Models are replaceable. Your judgment should compound.

## Version B — after the hero demo ships

### 0–10s

Visual: `WORK W-42`, `agents: 1`, then agent process dies.

Voiceover:

> Agents finish. Sessions disappear. Plans change.

### 10–20s

Visual: `agents: none`, `flow: alive`.

Voiceover:

> The work must continue.

### 20–35s

Visual: Work compiles Context Capsule, Graph v1, capability, and gate; Agent B appears.

Voiceover:

> Flowness keeps work as the stable object, then assembles agents, context, tools, and graphs from its current state.

### 35–52s

Visual: Finding shows missing consumer; Graph v1 fades into Graph v2.

Voiceover:

> When reality changes the answer, Flowness does not blindly retry. It finds the invalid assumption, reopens the affected slice, and compiles a new path.

### 52–67s

Visual: built/integrated green; activated unknown; Owner Inbox decision.

Voiceover:

> Humans do not supervise every transcript. They define the constitution—and return where value, authority, or irreversible effects make their judgment essential.

### 67–82s

Visual: organic activation, accepted, evidence manifest hash.

Voiceover:

> Completion is not a sentence. It is a chain from artifact to consumer, effect, evidence, and acceptance.

### 82–90s

Visual: Flowness mark.

Voiceover:

> Flow Engineering is the engineering of work in motion. Flowness is its software-engineering reference runtime.

On-screen:

> Work persists. Agents assemble.
