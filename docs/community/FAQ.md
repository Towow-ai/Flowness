# Frequently Asked Questions

## What is Flowness in one sentence?

Flowness is a work-centered runtime for agentic software engineering: Work persists, while Agents, contexts, tools, graphs, and gates assemble around its current state.

## Is it another multi-Agent framework?

It can coordinate multiple Agents, but Agent count is not the central abstraction. The central object is Flow; Work is the stable interface for querying its state across many execution attempts.

## Is Flow just a workflow?

A workflow usually names a process or graph. In Flowness, a Flow is the continuing causal process by which a goal, driven by events, is repeatedly compiled against the current world into executable structure, executed, verified, and committed. Work is the stable, addressable projection of that Flow—the interface through which humans and programs locate it—and it may cross several graph versions.

## Is this a replacement for LangGraph, Temporal, Prefect, OpenHands, or Claude Code?

No universal replacement claim is made. Those systems are relevant baselines and possible substrates or adapters. Flowness focuses on Flow-first state, current-world compilation, governed reflow, human constitutional control, and reality-bound closure.

## What can I run today?

The public Open Alpha provides a deterministic Assurance Kernel demo covering execution, independent review, targeted rework, and fresh acceptance. Broader mechanisms are exposed at different evidence levels; consult the claims register.

## Why does the README discuss things that are not fully public yet?

The project separates product direction from current proof using `[RUNNABLE]`, `[INSPECTABLE]`, `[DOGFOOD]`, `[DESIGNED]`, and `[OPEN QUESTION]`. A designed target is never presented as shipped behavior.

## Does Flowness remove humans from the loop?

No. It tries to remove humans from constant session supervision while preserving human control over goals, meaning, obligations, authority, red lines, acceptance, and irreversible effects.

## What is a Cognitive Exoskeleton?

It is the accumulated, executable judgment of a person or organization: goals, concepts, decisions, exceptions, obligations, skills, validators, acceptance standards, and failure history. Models can change while this judgment compounds.

## Why build a personal or organizational Harness instead of using one universal framework?

Harness value often increases as it becomes aligned with a real organization’s objects, evidence, habits, permissions, and definition of done. A general framework can provide the “scaffolding for scaffolding,” but should not silently overwrite local judgment.

## How can I contribute without adopting the whole runtime?

Use one of three paths:

- **Learn:** challenge a concept, case, or claim.
- **Borrow:** extract and test one mechanism or contract.
- **Build:** implement a WorkView, adapter, fixture, benchmark provider, or complete Flow profile.

## What contributions are most useful now?

Clean-room installation reports, reproducible failure fixtures, broken evidence links, adversarial evaluations, small mechanism implementations, and a real organic public end-to-end case.

## Where should conceptual debates happen?

Use GitHub Discussions. Use Issues for actionable defects, fixtures, benchmark work, and bounded implementation proposals.
